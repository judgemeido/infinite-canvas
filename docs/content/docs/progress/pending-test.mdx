# Pending Tests

The current release needs manual verification in these areas:

- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from either the background or a node. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: starting a resize while child images are expanded should collapse the group once, then resize the root node normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
- Branding and background: the top navigation should show the app name 「以诗为墨·神笔绘卷」 and the image workbench should be titled 「AIGC绘卷」 in the navigation and page heading; the page background should render bk.png as a subtle semi-transparent layer over the theme base color in both light and dark themes; the log, prompt, and result panels and cards inside the workbench should have transparent backgrounds so the background image shows through while text remains readable; the top-right corner should no longer show the version number, GitHub, Agent, or docs icons, and the workbench should no longer offer model selection (models are configured on the Settings page).
- Deployment and proxy: on the deployed site, generation requests should go through the same-origin /api proxy to change2pro (the browser network panel shows /api/v1/... paths without CORS errors); newly created channels should default to /api; visiting or refreshing /image and /config directly should not 404.
- Legacy config migration: if generation previously failed on the deployed site because the browser persisted an openai channel pointing directly at `https://api.change2pro.com` (or `https://api.openai.com`), reloading the page should automatically rewrite that channel's base URL to /api so generation works without manually clearing storage; gemini/ark channels and user-entered third-party URLs must not be rewritten.
- Prompt library content replacement: in the prompt library / prompt sources, the original 7 remote GitHub sources (Banana Prompt Quicker, Freestylefly, etc.) should no longer appear, leaving only the built-in "诗词风景 · 灵感提示词" source; it should load 100 poetry-scenery prompts filterable by style tags across ink-wash, blue-green landscape, gongbi, Dunhuang mural, ukiyo-e, impressionist, cyberpunk, Ghibli, pixel art, guochao illustration, etc.; clicking an entry shows its full prompt and can add it to assets, and returning users should no longer see the old sources or their cached content after refresh.
- Interactive quest: the home should redirect to /levels showing two level cards — Level 1 「诗词接龙」 and Level 2 「以诗为墨·神笔绘卷」 (cover/gradient, poem, task, status badge) plus a coming-soon placeholder, both playable via Start Challenge; Level 1 opens /poem-chain (read the first line, pick the next line; wrong lets you retry, correct advances; finishing shows a celebration with replay/back); Level 2 opens /image with a level banner and pre-filled starter prompt, and a successful generation marks it cleared (persisted) with a celebration; visiting /image without an active level falls back to the plain workbench.
- Poem chain by grade: Level 1's card should show its dedicated background image (h.png); opening /poem-chain should first present a Grade 1–6 picker, and choosing a grade should draw only that grade's textbook poems (28 questions total) with the first line as the prompt and next lines as options; the quiz view should offer "Change grade" to return to the picker; finishing shows a celebration and "Play Again" should redraw questions from the same grade; the page background should overlay the same level image while text stays legible.
- Poem quest (Grades 1–9, multi-format): Level 1 is renamed "古诗词大闯关"; opening /poem-chain should present a Grade 1–9 picker with each card showing its bank size (all ≥100); choosing a grade draws 10 random questions per round with a progress bar; multiple question types should appear (chain, guess-poem-by-meaning, name-the-poem, guess-line-by-author, guess-author-by-line, guess-dynasty-by-line, multi-select); for single-choice, a wrong option should shake and reveal a hint (source/title) while the correct option pops and auto-advances; multi-select shows a "Submit" button and requires all correct options; clearing 10 questions triggers a completion celebration with confetti and "Play Again" redraws the same grade; the page background should be h.png at opacity 0.1 over a warm gradient, staying legible and polished in both dark and light themes.
- Poem quest scoring mode: each round should have 15 questions (header shows "X / 15"); every question allows only one attempt — a single-choice pick locks immediately, multi-select locks after "Submit", and all options are then disabled; a correct answer shows "+10" and raises the "this round" score by 10, a wrong answer scores nothing and reveals "Wrong. Answer: … From …" with the correct option in green and the mis-picked option in red; after answering, a "Next" button appears ("See result" on the last question); both the picker and quiz header show "Total X pts · Y rounds", and finishing a round adds the round score to the total and increments the round count (persisted across refresh); the picker shows a "Reset score" action (with confirm) when there is history; replaying different grades accumulates the total.
- Poem quest difficulty & AI settlement: after picking a grade, a difficulty picker should appear (header "Choose difficulty for Grade X", back button "Change difficulty") offering Easy/Normal/Hard cards labelled "10/15/20 pts each" and "×1.0 / ×1.5 / ×2.0"; harder difficulties should surface more inference/multi-select question types and award the difficulty's per-question points on a correct answer; finishing 15 questions should pop a fake "AI settlement" modal with a progress bar, stepped calculations (read answers / difficulty weight / grade weight / accuracy bonus / final total) and a counting-up score, ending in a final "fair" score = correct × per-question points × grade weight × accuracy bonus; the completion modal is difficulty-aware (e.g. "Hard · Grade 3: 2 / 15 right, AI settled N pts") with Play Again (same grade+difficulty) / Back; the total accumulates by the settled final (e.g. Hard Grade 3 with 2 correct = 2×20×1.10×1.0 = 44); the header "Reset level" button opens a confirm dialog and, on confirm, clears the total to "0 pts · 0 rounds".
- Level card button alignment: on /levels, the Level 1 and Level 2 cards should bottom-align their "Start Challenge / Play Again" buttons on the same horizontal line even though the intros differ in length (Level 1 has a two-line intro, Level 2 one line), and both cards should be equal height.
- Level 2 workbench trimming: opening Level 2 /image, the workbench should no longer show any reference-image UI (drag-drop upload, clipboard paste, reference thumbnails, and the "Add as reference" button on result cards should all be gone) and generation always uses text-to-image; the aspect-ratio options should keep only the regular ratios (1:1, 3:2, 2:3, 4:3, 3:4, 16:9, 9:16) with no 2K/4K high-resolution tiers; the image count should keep only the "1 image" quick option plus a custom number input, with an amber note below reading "This site generates at most 20 images per run; please set a reasonable count." (localized) that is advisory only and does not actually block counts above 20; inserting an image asset from the asset library should warn "Image Studio currently only supports text assets".
